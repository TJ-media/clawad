# 개인정보 수집·보유·위탁 설계 (CLAW-15)

> ⚠️ **검토용 초안. 외부 공개 금지.** 미확정 플레이스홀더(§9)가 남아 있는 동안 이 문서와
> [privacy-policy-draft.md](privacy-policy-draft.md)를 실제 처리방침으로 게시하지 않는다.
> 최종 공개 전 개인정보 전문가 검토가 필요하다.
>
> 이 설계는 클라이언트/서버 구현(CLAW-24 이벤트 스키마, CLAW-28 파기)이 반드시 준수한다.
> 허용목록은 **실제 전송 스키마(§1)를 단일 기준**으로 하며, 문서가 코드보다 넓은 범위를 적지 않는다.

## 1. 수집 허용목록 (allowlist)

이 목록에 없는 데이터는 수집하지 않는다. 클라이언트는 아래 외 필드를 이벤트에 담지 않는다.

### 1.1 클라이언트가 실제로 전송하는 필드

`POST /v1/events` 본문 (참조 구현: `client/sync.js`) — **이 8개가 전부다.**

| 필드 | 내용 | 비고 |
|---|---|---|
| `serveToken` | 서버가 발급·서명한 불투명 토큰 | 클라이언트는 내용을 만들지 못한다 |
| `sequence` | 머신별 노출 순번(정수) | 멱등 키 재료 |
| `machineId` | 로컬 생성 랜덤 가명값 | 하드웨어 식별자 아님(§6) |
| `startedAt` / `endedAt` | **광고 표시(활성 유효 구간)** 시작·종료 timestamp | 세션 시각이 아니다 |
| `renderStarted` | **광고가 화면에 처음 렌더된 시각** timestamp (CLAW-71) | 선택적·진단 전용. 표시→유효 노출 퍼널 관측에만 쓰고 노출 인정·과금·리워드 판정에 쓰지 않는다. `startedAt` 이하이며, 세션 시각·프롬프트·경로가 아니다. 보유기간은 이벤트 원장과 동일 |
| `userId` | 인증된 사용자 식별자 | 서버가 세션·토큰으로 확정. 본문 자가신고값은 신뢰하지 않는다 |
| `clientVersion` | 클로애드 클라이언트 버전 | 최대 32자의 semver 허용목록. 자유 문자열은 거절 |

`POST /v1/machines` 본문: `userId`, `machineId`.

### 1.2 서버가 serveToken에서 추출해 저장하는 필드

클라이언트가 보내지 않는다. 서버가 토큰을 검증한 뒤 원장에 기록한다 (참조 구현: `server/index.js`의 `baseRec`).

- `tokenJti` — 토큰 `jti`. 멱등 키 재료
- `campaignId`, `campaignType` — 캠페인 식별자·유형(PAID/HOUSE/TEST)
- `idempotencyKey` = `SHA-256(tokenJti:machineId:sequence)`
- `decision`, `reason`, `confirmSeq`, `at`(서버 수신 시각)

> `creativeId`는 토큰 payload에 있으나 현재 원장에 저장하지 않는다. 저장을 시작하려면 이 목록을 먼저 갱신한다.

### 1.2.1 광고 결정 집계 로그 `ad_serve_log` (CLAW-71)

노출 퍼널의 첫 단계 "광고 결정(serveToken 발급)" 수를 시간범위로 세기 위한 append-only 집계 로그다.

- **저장 필드**: `campaignId`, `campaignType`, `creativeId`(nullable), `servedAt`(발급 시각). 이게 전부다.
- **사용자를 식별하지 않는다**: `userId`·`machineId`·`serveToken`·IP를 저장하지 않는다. 개인정보 이벤트 원장(`impression_events`)과 **조인하지 않는다**.
- **목적**: 발급 대비 표시 시작·유효 노출 전환율과 손실 구간 진단(운영자 콘솔 퍼널). 광고주·사용자 개별 식별이 아니다.
- **보유기간**: 운영 관측 목적의 집계 로그로, 이벤트 원장 보유정책에 준한다.

### 1.3 로컬에만 남고 전송하지 않는 값

`data/ledger.jsonl`, `data/work-state/*.json`, `data/sequence.json`, `data/machine.json`, `data/overlay-events/*.json`, `data/overlay-trigger.json`, `data/surface.lock`, `data/overlay-policy.json` — 사용자 기기를 떠나지 않는다.

- Claude Code의 `session_id`는 **활동 감지 훅**이 세션별 작업 구간을 구분하는 목적으로만 읽는다.
- 원문은 저장하지 않고 SHA-256 해시의 앞 32자를 로컬 상태 파일명으로만 사용한다.
- 원문과 로컬 해시는 이벤트 원장에 넣거나 서버로 전송하지 않는다.
- 작업 활성 상태에는 세션 해시, 훅 종류에 따른 시작·종료 시각만 저장한다. 프롬프트·경로·소스 내용은 읽거나 저장하거나 전송하지 않는다.
- `data/session-state/*.json`는 statusline 광고가 쓰던 로컬 상태였고 CLAW-134에서 없어졌다. 남아 있는 파일은 기기 안에만 있고, 새로 만들어지지 않는다.
- 오버레이 이벤트 스풀에는 표시한 광고의 `serveToken`, 광고 **표시 구간** 시각(`displayStartedAt`·`displayEndedAt`), 표시 시작 신호(`renderStarted`), 스키마 `version`만 담는다(CLAW-90, `docs/design/overlay-contract.md` §3.2). 수거 즉시 삭제하고, 보존기간을 넘긴 파일은 폐기한다. 스풀에 다른 키가 들어 있어도 원장·전송 스키마로 옮기지 않는다.
- 수거 트리거 포인터에는 클로애드 클라이언트의 실행 경로만 담는다. 사용자 파일 경로·환경변수·명령어를 담지 않으며 전송하지 않는다.
- 서피스 락(`data/surface.lock`)에는 소유 프로세스의 pid·획득 시각·소유자 문자열(`"overlay"`)만 담는다. 광고를 한 서피스에서만 표시하기 위한 조정 파일이고 전송하지 않는다 (CLAW-119, `docs/design/overlay-contract.md` §3.1).
- 오버레이 정책 캐시(`data/overlay-policy.json`)에는 표시 정책값(광고 교체 주기·유휴 임계·표시 폭·최소 시청 시간)만 담는다. 단가·상한·배분율은 담지 않으며, 사용자 데이터가 아니다 (§2.1 계약).

**오버레이 광고 런타임의 로컬 접근 범위 (CLAW-87)**

> 이 항목은 오버레이의 **광고 기능**(CLAW-90·119 구현분)에 한정된다. 오버레이 앱은 clawd-on-desk
> 포크이고, **포크가 물려준 다른 기능(에이전트 훅 통합 등)은 이보다 넓은 데이터를 단말 안에서 읽는다.**
> 그 항목은 전송되지 않으며 **§1.8에 고지**했다 (CLAW-127 결정). 전수 접근 지점은 **부록 A**.

- 광고 런타임이 **읽는** 것: `data/bundles.json`(광고 문구·토큰), `data/work-state/*.json`(활동 상태, 읽기 전용), `data/overlay-policy.json`, `data/overlay-trigger.json`. **쓰는** 것: `data/surface.lock`, `data/overlay-events/*.json`.
- 광고 표시용 활동 감지는 `client/work-activity.js` 훅이 만든 `work-state`만 읽어서 한다. **광고 런타임은 프로세스 열거·윈도우 타이틀 조회·트랜스크립트 읽기를 하지 않는다** — 세션 식별에 필요한 값은 이미 해시된 세션 키뿐이다. (앱의 다른 경로는 부록 A.2 참조)
- `renderStarted`는 오버레이에 광고가 처음 렌더된 시각이다. 표시 시작 진단(퍼널) 용도이며 **노출 인정·과금·리워드 판정에 쓰지 않는다**. 기존 허용목록 필드라 새 수집 항목이 아니다.
- 광고 클릭은 https 링크를 기본 브라우저로 열기만 한다. **클릭 대상·횟수를 기록하거나 전송하지 않는다** — 클릭 정보 수집은 별도 동의가 있을 때만 가능하다(§3 동의 분리).
- **전송 스키마는 변경되지 않았다.** 오버레이가 만드는 노출도 §1.1의 8개 필드로만 업로드되며, 스풀 파일은 서버로 가지 않고 clawad가 수거해 원장에 옮긴 뒤 삭제된다. 수집 항목·목적·보유기간이 그대로이므로 **개인정보처리방침 재동의 절차가 필요하지 않다**(처리방침 개정 사유 없음). 새 전송 필드가 필요해지면 §1.1과 처리방침을 함께 갱신한 뒤 진행한다.

- `slotKey`, `adId`, `synced`(전송 여부 불리언), 로컬 기록 시각

### 1.4 조건부 항목 (기능 도입 시에만)

- **클릭 정보** — 클릭 가능한 인벤토리(CLAW-7)가 실제로 존재하고, 그에 대한 고지·동의가 적용되는 경우에만 수집한다. 현재 클릭 기능이 없으므로 **수집하지 않는다.**

### 1.5 회원 인증 (CLAW-22·CLAW-37)

- **소셜 로그인 식별자**: 공급자(Google·Kakao·Naver)와 그 공급자가 발급한 안정적 계정 식별자(`providerSubject`), 동의 이력.
- 공개 로그인은 소셜 전용이다. 소셜 사용자의 이메일은 저장하지 않으며(`users.email`은 NULL), 이메일·닉네임·프로필은 계정 식별자로 쓰지 않는다. (EMAIL·GitHub 식별자는 legacy로만 존재하며 신규 로그인에 쓰지 않는다.)
- 공급자 access/refresh 토큰과 authorization code는 로그인 검증에 필요한 동안만 메모리에 두고 DB·Redis에 장기 저장하지 않는다. **로그인 목적의 이메일 scope는 요청하지 않는다** — 계정 식별은 `providerSubject`만으로 한다. 쿠폰 발송용 이메일은 공급자 scope가 아니라 §1.5.1의 별도 입력·동의로 수집한다.
- 내부 세션 토큰: access 토큰은 클라이언트 메모리에만 둔다. refresh 토큰은 웹에서 JS가 읽을 수 없는 httpOnly+Secure 쿠키(Path=/v1/auth), CLI에서 `data/auth.json`(0600)로 두며, 서버에는 SHA-256 해시만 저장하고 사용 시 원자적으로 1회 소비·회전한다(CLAW-37·38·41). localStorage 등 JS 접근 저장소에 토큰을 두지 않는다.
- 내 정보 내보내기(`GET /v1/me/export`)는 연결된 provider·subject와 교환 내역(발송 이메일 포함, 본인 데이터)을 포함하되 토큰·비밀번호 해시는 제외한다. 탈퇴·파기 시 모든 identities를 제거한다(CLAW-28).

### 1.5.1 쿠폰 발송 이메일 (CLAW-74)

- **수집 항목**: 리워드 교환 시 사용자가 직접 입력한 발송 이메일 1건(`redemptions.deliveryEmail`). 해당 교환의 스냅샷이다.
- **수집 목적**: 알파에서 운영자가 지정 상품(모바일 쿠폰)을 **수동 발송**할 대상 주소. 이 목적 외로 쓰지 않는다.
- **수집 시점·동의**: 교환 화면에서 매 교환마다 입력받고, 발송 목적의 수집·이용에 대한 명시적 동의(체크박스, 서버 `deliveryEmailConsent` 필수)를 함께 받는다. 미동의·형식 오류는 400으로 거절한다.
- **로그인 식별자로 쓰지 않는다.** `users.email`은 계속 NULL이며 발송 이메일과 분리된다. 자동완성·계정 프로필로 저장하지 않는다(개인정보 최소화 — 매 교환 재입력).
- **노출·마스킹**: 사용자 교환 내역과 운영자 지급 대기 목록에는 마스킹 값(`ab***@ex***.com`)만 노출한다. 운영자가 실제 발송을 위해 원문을 볼 때는 감사 기록되는 별도 액션(`POST /internal/v1/redemptions/:id/reveal-email`, SETTLER)으로만 확인한다. 이 응답 본문에 원문이 실리므로 엣지·프록시에서 응답 본문을 로깅하지 않는다.
- **로그 금지**: 발송 이메일 원문과 쿠폰 코드는 애플리케이션 로그·감사 파라미터에 남기지 않는다(감사 sanitizer가 `email` 키·이메일 형태 문자열을 마스킹, §6.5).
- **보유·파기**: 발송(DELIVERED)·취소·실패로 교환이 종결되면 `deliveryEmail`을 **즉시 NULL로 파기**한다. 미종결(REQUESTED) 교환이 남아 있으면 탈퇴를 막는다(`409 REDEMPTION_IN_PROGRESS`) — 발송/취소로 종결한 뒤 탈퇴한다. 탈퇴·파기 배치(retention sweep)는 잔여분을 정리한다. 동의 시각(`deliveryEmailConsentAt`)은 식별정보가 아니므로 이메일 파기 후에도 동의 증적으로 유지한다. 교환 상태·원장은 가명 userId로 유지된다.

### 1.5.2 만족도 설문 응답 (CLAW-97)

- **수집 항목**: `survey_responses` 테이블의 `userId`(가명 계정 식별자), `surveyVersion`, `answers`(문항 키 → 선택지 코드 또는 자유 응답 텍스트), `createdAt`. 대리키 `id`(uuid) 외에는 이 4개가 전부다.
- **수집 목적**: ① 서비스 개선을 위한 이용 경험 파악 ② 설문 완료 리워드를 **1인 1회**로 지급하기 위한 중복 확인. 이 목적 외로 쓰지 않는다.
- **계정 연결**: 리워드 지급 대상을 특정해야 하므로 응답을 계정과 연결해 저장한다. 익명 응답이 아니다. 설문 화면에 이 사실을 고지한다.
- **선택지 코드**: 자유 응답 2개 문항을 뺀 나머지는 서버가 정의한 고정 선택지 코드만 저장한다. 정의에 없는 문항 키·선택지는 저장 전에 400으로 거절한다.
- **자유 응답**: 제어문자를 제거하고 길이 상한(1,000자)을 넘으면 거절한다. 사용자가 스스로 개인정보를 적지 않도록 입력란에 안내를 둔다. 그럼에도 포함된 개인정보는 삭제 요청 시 응답 행과 함께 파기한다.
- **결합 금지**: 광고 노출 이벤트 원장(`impression_events`)과 조인하지 않는다. 접속 IP·하드웨어 식별자 컬럼을 두지 않는다(§2·§6.6).
- **보유·파기**: 탈퇴 시 `PrivacyService.withdraw`가 응답 행을 **명시적으로 삭제**한다. 탈퇴는 `users` 행을 지우지 않고 가명화하므로 FK CASCADE가 걸리지 않는다 — CASCADE에 의존하지 않는다. 파기 건수는 `destruction_logs.detail.surveyResponsesDeleted`에 남는다.
- **열람권**: 내보내기(`GET /v1/me/export`)에 `surveyResponses`로 포함된다.
- **삭제권**: 탈퇴(`DELETE /v1/me`)하면 자동 파기된다. 탈퇴하지 않고 설문 응답만 삭제하려는 요구는 **전용 API가 없으므로 문의 창구(privacy-contact) 접수 → 운영자가 해당 행을 삭제하고 `destruction_logs`에 기록**하는 수동 절차로 처리한다. 자유 응답에 이용자가 스스로 적은 개인정보도 함께 파기된다. 적립된 리워드 원장 항목은 가명 userId 기준으로 회계 목적상 유지된다(§7.1).

### 1.6 허용목록에서 제거한 항목 (실제 미수집)

아래는 이전 초안의 허용목록에 있었으나 **코드 어디에서도 수집하지 않는다.** 문서가 코드보다 넓은 범위를 선언하지 않도록 제거했다. 다시 추가하려면 수집 목적·보유기간·전송 여부를 정한 뒤 이 목록과 처리방침을 함께 갱신한다(AGENTS.md §"새 이벤트 필드").

- ~~운영체제 종류~~ — 전송 스키마에 없음
- ~~Claude Code 실행 여부(불리언)~~ — 수집·검증에 사용하지 않음
- ~~세션 시작·종료 시간~~ — `startedAt`/`endedAt`는 **광고 표시** 구간이지 세션 구간이 아니다
- ~~오류 로그~~ — 클라이언트가 서버로 오류를 전송하지 않음
- ~~`syncedAt`~~ — 전송하지 않는다. 로컬 `synced` 불리언과 서버 수신 시각 `at`으로 대체

### 1.7 운영 모니터링 집계 (CLAW-65)

운영 모니터링은 새로운 클라이언트 이벤트나 필드를 수집하지 않는다. 서버가 이미 처리한 요청과 append-only 원장에서 다음 **집계값만** 계산한다.

- 고정 route family별 요청 수·상태 코드 범주·지연시간 구간
- OAuth 공급자와 고정 처리 단계별 성공·취소·안전한 내부 오류 코드 합계
- 이벤트 업로드의 수신·승인·거절 건수와 `서버 수신 시각 - endedAt` 지연시간 구간
- 노출 판정·거절 사유, 리워드 원장 유형별 건수·합계, 가장 오래된 미확정 건의 경과시간
- PostgreSQL·Redis 준비 상태, 활성 kill switch 대상 유형별 개수, 배포 commit

메트릭 label·대시보드·알림에는 URL/query/body, userId, machineId, campaignId, token/JTI, OAuth code/state/subject, 이메일, IP, 파일·프로젝트 경로, 프롬프트, 예외 메시지를 넣지 않는다. 동적 경로는 고정 route family로만 분류한다. Prometheus 보유기간은 운영 설정으로 제한하고 원장과 조인 가능한 원시 식별자를 내보내지 않는다. 클라이언트 네트워크 단절 자체는 서버가 관측했다고 추정하지 않으며, 서버가 실제 받은 sync 요청과 업로드 지연만 보고한다.

OAuth 경보용 단조 증가 counter는 고정 provider·단계·안전 오류 코드의 비식별 합계만 Redis에 보관하며
서비스 수명 또는 명시적 metrics reset까지 유지한다. 일자별 운영 집계는 설정된 보유기간 후 만료하고,
Prometheus 시계열은 운영 retention 설정에 따라 별도로 만료한다.

### 1.8 단말 내에서만 처리하는 항목 (CLAW-127, 2026-07-28 결정)

오버레이 앱은 clawd-on-desk 포크다. 포크의 표시 기능이 단말 안에서 읽는 항목을 **차단하지 않고 고지**하기로
결정했다. 아래가 그 전부이며, **운영자 서버로 전송되지 않는다** — 운영자는 이 값을 취득하지 않는다.

| 읽는 데이터 | 어디에 쓰이는가 | 접근 지점 | 전송 |
|---|---|---|---|
| 프롬프트 첫 줄 | 여러 작업 세션을 구분하는 표시용 이름 | `hooks/clawd-hook.js` `extractPromptTitle()` | 없음 |
| 대화 기록 파일 일부(최근 항목) | 컨텍스트(토큰) 사용량 게이지 | 같은 파일 `readTranscriptTailEntries()` + `hooks/context-usage.js` | 없음 |
| 작업 폴더 경로(`cwd`) | 세션이 어느 프로젝트인지 표시 | `hooks/clawd-hook.js`, `hooks/claude-statusline.js` | 없음 |
| 프로세스·터미널 창 식별 정보 | 클릭 시 해당 터미널 창으로 이동 | `hooks/clawd-hook.js`(`pid_chain`·`tmux_socket`·`wt_hwnd`) | 없음 |
| Codex 대화 기록 경로·첫 메타 레코드 | Codex 세션 식별·표시 | `hooks/codex-hook.js` | 없음 |
| Claude 구독 쿼터(`rate_limits`)·모델명·컨텍스트 사용률 | 쿼터 링·대시보드의 잔여 사용량 표시 | `hooks/claude-statusline.js` (CLAW-134) | 없음 |

**statusLine 슬롯 (CLAW-134·136, 2026-07-29).** Claude Code의 `statusLine` 슬롯은 하나뿐이고, 0.1.11까지는
clawad의 광고 상태줄이 그것을 쓰고 있었다. 광고 창구를 오버레이로 일원화하면서 clawad는 슬롯을
**점유하지 않게 됐고**(`client/statusline*.js` 제거), 그 자리를 오버레이의 쿼터 수집 어댑터가 쓴다.
이 어댑터는 Claude Code가 stdin으로 주는 텔레메트리에서 위 표의 마지막 행만 읽어 **같은 단말의
오버레이 프로세스에 전달**한다(localhost). 운영자 서버로는 나가지 않는다.

CLAW-136에서 이 수집을 **기본 활성**으로 바꿨다. 슬롯을 비워도 사용자가 직접 켜지 않으면 쿼터가
수집되지 않아 CLAW-134의 목적이 달성되지 않기 때문이다. 기본 활성으로 두는 조건은 다음과 같고,
하나라도 깨지면 기본값을 되돌린다.

1. **전송 없음** — §1.1의 8필드는 그대로다. 이 값들은 원장·서버 API·서버 로그에 없다.
2. **남의 설정을 덮어쓰지 않음** — 슬롯이 비었거나 이미 우리 것일 때만 점유한다. 사용자가 쓰던
   statusLine이 있으면 그대로 두고 수집을 포기한다.
3. **끄고 되돌릴 수 있음** — 오버레이 설정에서 끄면 등록이 해제되고, 앱 제거 시에도 해제된다
   (`hooks/cleanup-integrations.js`). 설치 전 고지는 CLI 설치 안내에 포함한다(규칙 §7).
4. **광고를 그 자리에 렌더하지 않음** — 이 슬롯에는 사용량 표시만 쓴다. 광고 창구는 오버레이 하나뿐이라는
   CLAW-134의 결정을 되돌리지 않는다(규칙 §3).

**지켜야 하는 조건** (이 중 하나라도 깨지면 결정을 재검토한다)

1. **전송 금지 유지** — §1.1의 8필드 외에 아무것도 나가지 않는다. 위 항목은 원장·API·서버 로그에 없다.
2. **광고 경로 분리** — 광고 표시·노출 인정·리워드 계산은 위 항목을 읽지 않는다(부록 A.4). 광고 런타임은
   `bundles.json`·`work-state`·정책 캐시·트리거만 읽는다.
3. **외부 전송 기능은 제거 우선, 남는 것은 기본 비활성** — 원격 승인(텔레그램·페이슈)과 모바일 프리뷰
   서버는 **제거했다**(CLAW-129, 2026-07-29). 남아 있는 외부 전송 경로(Discord 활동 표시 등)는 기본 off이고,
   켜는 화면에서 전송 대상을 고지한다(부록 A.3). 이들은 §5 제3자 제공 판단 대상이다(CLAW-94).
4. **고지 없는 확장 금지** — 새 단말 내 접근을 추가하려면 이 표와 처리방침 제1장 바.를 먼저 갱신한다.
5. **clawad 본체는 계속 미접근** — sync·수거·`client/*`는 훅이 만든 활성 구간(`work-state`)만 읽는다.
   clawad는 statusLine 슬롯을 점유하지 않으므로 Claude Code 텔레메트리를 아예 받지 않는다(CLAW-134).

**왜 차단이 아니라 고지인가**

- 이 데이터는 **표시 목적이 분명하고 단말을 벗어나지 않는다.** 운영자가 취득하지 않으므로 수집 항목이
  늘어나지 않고, 처리 목적·보유기간도 변하지 않는다.
- 대안은 포크 훅에서 해당 필드를 제거하는 것이었다. 그 경우 세션 표시 이름·컨텍스트 게이지·터미널 이동
  기능을 잃는다. 오버레이의 제품 가치가 그 표시 기능에 있다고 판단해 기능을 유지하고 투명 고지를 택했다.
- 감수하는 위험: "광고 클라이언트가 프롬프트를 읽는다"는 인식. 이를 상쇄하기 위해 (a) 소스코드 공개로
  검증 가능하게 두고, (b) 광고 경로와 표시 경로를 코드에서 분리하고, (c) 처리방침에 전송 없음을 명시한다.
- 처리방침은 v2 → **v3**으로 개정했다(시행일 2026-07-28). 전송 항목 무변경이지만 단말 내 처리 고지를
  신설했으므로 버전을 올렸다. 개정 시점에 실사용자가 없어 재동의 부담이 없었다.

## 2. 구조적 수집 금지 (denylist)

아래 항목은 **서버로 전송하지 않는다** — 이벤트 원장·API·서버 로그 어디에도 남기지 않는다.
clawad 본체(`client/*`: sync·수거·훅)는 **접근 자체를 하지 않도록** 구현한다(정책 아닌 구조로 차단).

> **예외 — 오버레이의 단말 내 표시 처리 (2026-07-28, CLAW-127 결정)**
> 데스크탑 오버레이(clawd-on-desk 포크)의 표시 기능은 단말 안에서 아래 중 일부를 읽는다.
> **전송하지 않으므로 운영자는 그 값을 취득하지 않는다.** 차단 대신 **고지**를 택했고, 항목·목적은
> §1.8과 처리방침 v3 제1장 바.에 명시했다. 광고 표시·노출 인정·리워드 경로는 이 항목들을 읽지 않는다.
> 결정 근거와 대안 비교는 §1.8, 실제 접근 지점은 부록 A에 있다.

- 프롬프트 본문, Claude 응답 내용, 코드 내용
- 파일명·프로젝트 경로, Git 저장소명
- 터미널 명령어, 환경변수, 클립보드
- 회사명 추론 정보(레포·경로·코드로부터의 유추 포함)
- **하드웨어 식별자: MAC 주소, 디스크 시리얼, 하드웨어 UUID** (수집·전송 금지)
- **접속 IP** — 제품 이벤트 데이터로 수집하지 않는다(§6.6)

동시 노출 판정(CLAW-18 §6)에 필요한 최소 데이터만 수집한다: userId, 가명 machineId, startedAt/endedAt, sequence. 그 외 필드를 판정을 이유로 추가하지 않는다.

## 5. 처리위탁 vs 제3자 제공

- **쿠폰 지급대행사**: 클로애드 지시에 따라 발송만 수행 → **처리위탁**으로 본다. 위탁계약서에 처리 목적·항목·기간·재위탁 제한·안전조치 명시.
- 공급사가 독립 목적으로 정보를 사용하면 제3자 제공에 해당 → 이 경우 별도 동의·고지 필요. **계약 단계에서 위탁 구조로 못박는다.**
- 위탁 시에도 처리방침에 수탁자·업무 내용을 공개한다.

## 6. 가명 머신 ID 규칙

- MAC 주소·디스크 시리얼·하드웨어 UUID 등 하드웨어 식별자를 수집·전송하지 않는다.
- 로컬에서 생성한 **랜덤 가명값**을 머신 식별자로 사용한다(참조 구현: `client/machine.js`의 `getMachineId`, `crypto.randomBytes(16)`).
- 하드웨어 식별자를 쓰지 않으므로 "동일 기기를 완벽 식별한다"거나 "동일 지문 다계정을 확정 탐지한다"고 표현하지 않는다(CLAW-19).
- 서버는 이 가명 ID로 상한·동시노출·위험 신호만 판단하고, 실사용자 신원과 직접 연결하지 않는다(회원 매핑은 별도 최소 권한).

## 6.5 로그 마스킹

- 로그에 serveToken 전체 값, 인증 토큰, 이메일, 쿠폰 수신 정보 등을 남기지 않는다(필요 시 마스킹·해시).
- 감사로그의 요청 값은 민감 키·토큰·이메일·경로 패턴을 마스킹한다. 알 수 없는 서버 예외는 SQL,
  파라미터, stack, 요청 URL을 로거에 넘기지 않고 고정 코드 `UNHANDLED_REQUEST_EXCEPTION`만 기록한다.

## 6.6 접속 IP 처리 (제품 데이터 아님)

IP는 **제품 이벤트 데이터의 정식 수집 항목이 아니다.** 클라이언트는 IP를 전송하지 않으며, 서버 원장(`events.jsonl` / 운영 4원장)에 IP 컬럼을 두지 않는다.

**금지:**

- 광고 이벤트 DB에 IP를 저장하는 것
- IP를 타겟팅 신호로 사용하는 것
- IP로 고유 사용자·동일인·다계정을 판단하는 것 (동시 노출·상한 판정은 `userId` + 가명 `machineId`만 사용 — §2, CLAW-19)

**허용(불가피한 전송계층 처리):**

- 웹 서버·리버스 프록시·WAF·DDoS 방어 등 인프라·보안 로그에는 TCP 연결의 성격상 IP가 일시적으로 기록될 수 있다.
- 이 로그의 IP는 **기록 즉시 마스킹(예: 마지막 옥텟 절삭)하거나, 마스킹이 불가능한 보안 목적에 한해 짧은 보유기간 후 삭제**한다.
- 인프라 로그는 광고 이벤트 원장과 물리적·논리적으로 분리하며, 서로 조인하지 않는다.
- 보유기간·마스킹 방식은 `[미확정: 인프라 구성(CLAW-27) 확정 후 기입. 외부 공개 전 필수]`.

- 구현 연계: CLAW-24(이벤트 스키마 필드 제한), CLAW-28(조회·탈퇴·파기), CLAW-27(접근통제·감사로그)

### 7.1 이용자 권리 구현 (CLAW-28, 구현됨)

- **조회·내보내기**: `GET /v1/me/export` — 수집 항목 전체를 기계 판독 JSON으로. 비밀번호 해시는 제외한다.
- **탈퇴·파기**: `DELETE /v1/me` — 즉시 서비스 이용 중단(기존 토큰·로그인 차단) + 직접 식별자 파기·가명화.
  - **append-only 원장(노출·리워드·과금)은 삭제하지 않는다.** userId는 가명 UUID이며, 세무·정산·분쟁 보관 의무가 있다. 대신 로그인 수단(identities)·회원 이메일·교환행의 발송 이메일(`redemptions.deliveryEmail`, CLAW-74)을 파기해 신원 연결을 끊는다.
  - 미지급 **확정 리워드**가 있으면 탈퇴를 차단한다(`409 UNPAID_CONFIRMED_REWARDS`). 교환(CLAW-26) 후 탈퇴하거나 포기에 명시 동의해야 한다. 포기 시 반대 분개(ADMIN_ADJUST)로 잔액을 0으로 만든다.
  - 탈퇴 계정의 검증 중 리워드는 확정 배치에서 확정되지 않는다(신원 파기 계정에 확정잔액이 생기지 않게).
- **파기 로그**: `destruction_logs`(append-only). 파기된 값을 복제하지 않고 항목명·건수만 기록.
- **파기 배치**: `POST /internal/v1/privacy/run-retention-sweep`(SUPERADMIN) — 탈퇴 계정 잔여 식별자 정리. **보유기간 경과 원장 자동 파기는 세법상 보관연수 확정(CLAW-13) 후 확장한다.**
- **접속 IP**: 제품 이벤트로 수집하지 않으므로 파기 대상이 없다(§6.6). 인프라 로그의 IP 처리는 운영 절차([secrets-and-backup.md](../security/secrets-and-backup.md) §4).

## 부록 A. 포크 데이터 접근 감사 (CLAW-87)

오버레이 클라이언트(`clawad-overlay`)는 clawd-on-desk 포크다. **"접근하지 않는다"는 선언만으로는
부족하므로**, 포크가 물려준 코드가 실제로 무엇을 읽는지 전수 확인했다.

- 감사 기준: 2026-07-28, `clawad-overlay` main (앱 0.13.0)
- 판정 기준: 본 문서 §2(구조적 수집 금지)와 규칙 `.claude/rules/clawad.md` §6
- 기본값 확인 방법: `src/prefs.js`의 `getDefaults()` 실행값

### A.1 결론

**기본 활성 경로가 단말 안에서 프롬프트 첫 줄·대화 기록·경로·프로세스 정보를 읽는다.** 서버로는
전송되지 않는다(전송 필드는 §1.1의 8개뿐).

2026-07-28 결정(**CLAW-127**): 이 접근을 **차단하지 않고 고지**한다. 항목·목적·조건은 §1.8,
이용자 고지는 처리방침 v3 제1장 바.에 있다. 아래 A.2는 "차단 대상"이 아니라 **고지 대상 목록**이며,
§1.8의 5개 조건(전송 금지·광고 경로 분리·외부 전송 기본 비활성·고지 없는 확장 금지·clawad 본체 미접근)이
유지되는지 확인하는 체크리스트로 쓴다.

### A.2 기본 활성 — 단말 내 처리 (고지 대상, §1.8)

| 기능 | 접근 대상 | 근거 | 판정 |
