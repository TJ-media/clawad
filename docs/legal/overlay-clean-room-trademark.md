## 1. AGPL 격리 — 원래 계획에서 방향이 바뀌었다

이 이슈 본문은 "clawd-on-desk **소스 열람·인용·복제·파생 금지**"를 요구했다. 그 전제는
**2026-07-24 CLAW-86 결정으로 바뀌었다** — 클린룸 재구현 대신 **AGPL 포크**를 택했고, 대신
**저장소를 분리해 카피레프트를 격리**한다. 따라서 지금의 점검 대상은 "오염 차단"이 아니라
"격리가 실제로 유지되는가"다.

**검증 결과 — 격리 유지됨**

- `clawad-overlay`(AGPL 포크)에서 `clawad`의 코드를 `require`/import하는 지점: **없음**.
- `clawad`에서 오버레이를 참조하는 지점: 주석 2곳(`client/cli.js`, `client/overlay-events.js`)뿐이며
  코드 의존이 아니다.
- 두 프로그램의 접점은 **문서화된 로컬 파일 협약과 HTTP API**뿐이다
  (`docs/design/overlay-contract.md`, `clawad-overlay/docs/BOUNDARY.md`).
- 서버 코드는 오버레이에 배포되지 않고, 오버레이 코드는 서버에 링크되지 않는다.

**kickbacks.ai 클린룸 원칙은 별개로 계속 유효하다.** 오버레이가 clawd-on-desk 포크라는 사실이
kickbacks.ai 원본 코드 열람 금지를 완화하지 않는다. 두 계보를 혼동하지 않는다 —
clawd-on-desk는 데스크탑 펫(AGPL), kickbacks.ai는 광고·리워드 제품(source-available 비오픈소스)이다.

## 2. AGPL §13 — 모바일 프리뷰 제거로 해소

점검 시점의 `clawad-overlay`에는 `src/network/mobile-preview-server.js`가 있었다. 파일 첫 줄에
스스로 적어둔 대로 **정적 PWA 파일과 WebSocket을 `0.0.0.0`에 바인딩**해 같은 네트워크의 휴대전화에서
접속할 수 있게 했다(토큰 게이트, 기본 비활성 `mobilePreviewEnabled: false`).

AGPL-3.0 §13은 수정된 프로그램을 **네트워크를 통해 원격 이용자와 상호작용**시키는 경우
그 이용자에게 Corresponding Source를 받을 기회를 **눈에 띄게 제공**하라고 요구한다. 우리 소스는
공개 저장소에 있어 의무 이행 자체는 가능했지만, "눈에 띄게 제공"을 충족하려면 그 PWA 화면에
소스 저장소 링크가 있어야 했다.

**해소 (2026-07-29, CLAW-129)** — 모바일 프리뷰 서버와 `pwa/` 자산을 제거했다. 오버레이는 더 이상
원격 이용자와 네트워크로 상호작용하지 않으므로 §13 고려가 사라졌다. 되돌아오지 않는지는 아래로 지킨다.

- 같은 결정으로 원격 승인 브리지(텔레그램·페이슈)도 제거했다 — 프라이버시 관점(CLAW-127 §1.8 조건 3)의
  외부 전송 경로였고, upstream의 사이드카→네이티브 전환이 미완성이라 실제로 동작하지도 않았다.
- 남아 있는 외부 전송 경로는 Discord 활동 표시뿐이다. 이것은 **원격 이용자가 우리 프로그램과
  상호작용하는 구조가 아니라** 외부 서비스로 상태를 내보내는 단방향 전송이므로 §13 대상이 아니다.
  다만 제3자 제공(처리방침 §4) 판단과 upstream 앱 ID 교체는 남아 있다 (§3).

> 서버(`clawad`)는 AGPL 코드를 포함하지 않으므로 §13이 서버로 번지지 않는다. 이 격리가 §1의 목적이다.

## 3. 아트워크·제3자 자산

**upstream 아트워크는 전량 제외됐다** (`clawad-overlay/apps/client-desktop/FORK.md` §2).
upstream의 아트는 AGPL 대상이 아니라 All Rights Reserved이고, Clawd 캐릭터는 상업적 사용이
금지돼 있어 광고 매체인 클로애드가 쓸 수 없다. 히스토리도 잇지 않았다(아트 커밋 96개 존재).

- 우리 마스코트(픽셀 랍스터)만 사용하고, ARR 표기를 두 곳에 뒀다:
  `themes/clawad/LICENSE`(테마 아트), `assets/LICENSE`(앱·트레이·히어로 아트, CLAW-120).
- 제3자 자산 고지 유지: `NOTICE.md`의 OpenClaw 픽셀 랍스터 아이콘(MIT, © 2025 Peter Steinberger).
- upstream의 `LICENSE`(AGPL 전문)와 `NOTICE.md`는 보존한다. 삭제·수정하지 않는다.

**발견 — upstream ARR 아트를 원격 참조하는 지점이 있었다.**
`src/discord-presence-rpc.js`가 Discord Rich Presence 이미지로
`raw.githubusercontent.com/rullerzhou-afk/clawd-on-desk/main/assets/icon.png`를 참조했다.
기본 비활성 기능이지만 켜지면 **타인의 ARR 아트를 우리 제품 표시에 사용**하게 된다.
→ 이번 점검에서 해당 원격 이미지 사용을 제거했다.

## 4. 오인 표현 점검 (규칙 §7)

**"Claude 공식 서비스"로 오인될 표현: 없음.** i18n·설정 문구를 훑은 결과 Anthropic의 승인·제휴를
주장하는 표현은 없다. `Codex의 official approval hook`, `Claude Code의 official status-line payload`처럼
**타 도구의 공식 인터페이스를 가리키는 표현**은 사실 서술이므로 문제 없다.

**발견 1 — 거짓 소유 주장 (이번에 수정).** CLAW-126 브랜딩 치환의 부작용이다.
Discord Presence 설명이 `official Claw-Ad application`(공식 클로애드 애플리케이션)이라고 표기했는데,
기본 앱 ID `1525141423328854179`는 코드 주석대로 **upstream("Clawd on Desk")의 Discord 앱**이다.
치환이 `Clawd` → `Claw-Ad`를 적용해 "upstream 앱"이 "우리 공식 앱"으로 바뀌었다.
→ 5개 로케일 문구를 소유를 주장하지 않는 표현으로 고쳤다. 기본 앱 ID 자체는 **우리 앱으로 교체하거나
기능을 제거해야** 하며, 그 전까지 기본 비활성을 유지한다.

**발견 2 — README가 우리 제품을 Anthropic 팬 프로젝트로 서술한다 (후속 이슈).**
`clawad-overlay`의 `README.md`(및 ko/ja/zh 번역)에 upstream 문장이 그대로 남아 있다:
"**Clawd** 캐릭터는 Anthropic의 자산입니다. 이 프로젝트는 비공식 팬 프로젝트이며 Anthropic과
제휴하거나 승인받지 않았습니다."

- 우리는 Clawd 캐릭터를 **반입하지 않았고** 자체 마스코트만 쓴다. 이 문장은 **사실과 다르다.**
- 공개 저장소 첫 화면이라 노출도가 가장 높고, "우리가 Anthropic 캐릭터를 쓴다"는 오해를 만들어
  **상표 리스크를 오히려 키운다**.
- upstream 저작권 고지 의무는 `LICENSE`·`NOTICE.md`·`FORK.md`로 이미 충족되므로, README의 제품 설명은
  우리 사실에 맞게 다시 써야 한다. README 전반이 upstream 기능 설명이라 분량이 커서 후속 이슈로 분리한다.

## 5. 제품명 상표 리스크

### 5.1 사실관계

- Anthropic은 Claude 제품군을 운영하고 마스코트로 **Clawd**(랍스터)를 쓴다.
- **Clawdbot**은 Anthropic의 상표 관련 요청으로 **Moltbot**을 거쳐 **OpenClaw**로 개명한 전례가 있다.
  같은 생태계의 서드파티 도구가 실제로 개명까지 갔다는 점이 이 검토의 출발점이다.
- 우리 표기: 영문 **Claw-Ad**, 한국어 **클로애드**. 도메인 `clawad.whatsup.house`,
  저장소 `clawad`·`clawad-overlay`, appId `ai.clawad.overlay`, Jira 키 `CLAW`.

### 5.2 리스크 요소

1. **한국어 표기가 영문보다 더 가깝다.** Claude의 국내 통용 표기는 "클로드"이고 우리는 "클로애드"다.
   1음절 차이이며, 영문(`Claw-Ad` vs `Clawd`)보다 혼동 여지가 크다. 브랜딩(CLAW-126)에서 한국어를
   "클로애드"로 통일했으므로 이 리스크는 지금 확정된 상태다.
2. **상품·서비스가 인접하다.** 우리 제품은 Claude Code 이용자를 대상으로 하는 부가 도구다.
   혼동 우려 판단에서 상품 유사성은 핵심 요소이며, 여기서는 유사성이 인정될 가능성이 높다.
3. **캐릭터도 랍스터다** (§5.3).
4. 이름이 인프라 전반에 박혀 있다 — 도메인·저장소·패키지·appId·문서·Jira 키.

**완화 요소**: 하이픈 표기(`Claw-Ad`)가 "Claw + Ad(광고)"로 분절돼 광고 매체임을 드러낸다.
Anthropic 무관을 문서에 명시할 수 있다. 캐릭터 아트는 자체 제작이고 upstream 아트를 쓰지 않는다.

**판정: 중간~높음.** 법적 침해 여부는 변리사 판단 영역이지만, **권리자 요청으로 개명하게 될
실무 리스크**는 전례가 있어 실질적이다.

### 5.3 캐릭터 시각적 구별

우리 마스코트는 자체 제작 픽셀 랍스터다. 다만 **모티프 자체가 겹친다** — Anthropic의 Clawd도,
OpenClaw의 아이콘도 랍스터다. 아트 파일은 완전히 독립이지만 "붉은 픽셀 랍스터"라는 인식 층위에서는
구별이 약하다. 개명하지 않기로 정하면 **캐릭터 차별화**(색·형태·소품)를 별도로 검토해야 한다.

### 5.4 대응안

| 안 | 내용 | 비용 | 리스크 |
|---|---|---|---|
| **A. 현행 유지 + 완화** | 하이픈 표기 고정, Anthropic 무관 명시, 캐릭터 차별화, 상표 출원으로 선점 시도 | 낮음 | 권리자 요청 시 뒤늦게 개명 → 비용 폭증 |
| **B. 선제적 개명** | 지금(사용자 0·릴리스 0) 이름 교체 | 아래 §5.5 | 브랜드 인지 손실 없음(아직 없음) |
| **C. 조건부 보류** | 변리사 검토 + Anthropic 브랜드 가이드라인 확인 후 A/B 결정 | 자문료 | 결정 지연 — 단, 배포 전이라 감당 가능 |

**권고: C → 결과에 따라 A 또는 B.** 지금은 배포 전이라 개명 비용이 최저인 구간이고, 반대로 출시 후
개명은 도메인·설치본·처리방침까지 번진다. 결정을 미루더라도 **공개 배포 전에는 끝내야** 한다.

그친다. 출시 후에는 설치본 마이그레이션과 방침 재동의가 실사용자에게 발생한다.
