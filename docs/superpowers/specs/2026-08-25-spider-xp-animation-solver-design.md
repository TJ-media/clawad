# Windows XP형 스파이더 연출·검증 딜 설계 (CLAW-279)

## 목표

현재 스파이더 카드놀이를 공개된 Windows XP판의 관찰 가능한 배치와 동작에 가깝게 조정하고, 무작위 딜을 그대로 제공하는 대신 실제 해답이 확인된 딜만 시작한다. 난이도별 솔버 처리 시간을 동일한 로컬 환경에서 계측해 실시간 검증과 사전 검증 풀 중 어느 경로를 사용할지 결정한다.

## 클린룸·자산 원칙

- Microsoft 실행 파일, DLL, 카드 이미지, 아이콘, 사운드, 원본 코드는 다운로드·추출·복제하지 않는다.
- 공개 스크린샷과 플레이 영상에서 관찰되는 위치, 크기 관계, 이동 순서, 타이밍만 독자 구현한다.
- 카드는 현재 저장소의 CC0 `english-pattern-playing-cards@2x.png`를 계속 사용한다.
- XP풍 창 프레임은 클로애드의 기존 HTML/CSS 컴포넌트를 유지한다.

## XP형 레이아웃

게임판은 다음 네 영역으로 재배치한다.

1. 상단 메뉴: `게임(G)`, `카드 나누기(D)`, `도움말(H)`를 XP식 메뉴 줄에 둔다. 게임 메뉴에서 새 게임 난이도, 실행 취소, 힌트를 선택할 수 있고 현재 난이도는 라디오 체크로 표시한다.
2. 테이블: 10개 열을 상단 전체 폭에 균등 배치한다. 세로 겹침 간격만 창 높이에 따라 줄이며 카드 폭과 종횡비는 유지한다.
3. 하단 왼쪽: 완료한 K~A 묶음을 왼쪽부터 최대 8개 표시한다. 완료 묶음은 해당 무늬의 킹 카드가 보이는 작은 겹침 스택으로 그린다.
4. 하단 중앙·오른쪽: 중앙의 오목한 상태 패널에 `점수`와 `이동`을 표시하고, 오른쪽 아래에는 남은 배분 횟수만큼 카드 뒷면 묶음을 최대 5개 겹쳐 표시한다.

작은 창에서도 하단 세 영역의 좌우 기준점은 유지한다. 테이블 열만 가로 간격을 줄이며, 최소 지원 폭 아래에서는 게임판 내부를 가로 스크롤하지 않고 전체를 비율 축소한다.

기준 해상도 960×719에서 공개 XP 스크린샷과 주요 기준점의 차이는 8px 이내로 맞춘다. 공개 영상은 저속 재생으로 프레임을 기록하고 완료 이동의 총시간·카드 간 시차를 ±50ms 범위로 맞춘다. 이는 관찰 가능한 동작의 재현 기준이며 원본 픽셀 자산 복제를 뜻하지 않는다.

## 완성 묶음 애니메이션

### 동작

- 규칙 엔진은 기존처럼 성공한 이동 또는 배분 한 번 안에서 K~A 완성을 즉시 확정한다.
- UI는 연산 전후의 열 길이와 연산 종류를 비교해 어느 열에서 몇 묶음이 제거됐는지 순수 함수로 계산한다.
- 확정된 보드는 먼저 렌더하되, 제거된 13장을 나타내는 임시 카드 레이어를 원래 열의 마지막 카드 위치에 겹친다.
- K부터 A까지 13장이 짧은 간격으로 한 점에 압축된 뒤, 다음 빈 완료 슬롯으로 빠르게 미끄러져 들어간다. 목적지에서는 킹 카드가 보이는 완료 스택으로 정착한다.
- 여러 묶음이 한 연산에서 완성되면 왼쪽 슬롯부터 한 묶음씩 순차 재생한다.
- 여덟 번째 묶음이 정착하면 XP판의 관찰 가능한 승리 연출을 독자 CSS로 재현한다. 녹색 판 위에 짧은 불꽃 입자와 카드 탄성 이동을 보여주되 Microsoft 그래픽은 사용하지 않는다.

### 생명주기와 접근성

- 연출 중에는 스파이더의 클릭, 드래그, 키보드 명령을 잠근다.
- `새 게임`, 일시정지, 최소화, 종료, 재마운트는 진행 중 연출과 예약 콜백을 즉시 취소한다.
- `prefers-reduced-motion: reduce`에서는 임시 레이어 없이 완료 슬롯만 즉시 갱신한다.
- 임시 카드는 `aria-hidden="true"`로 두고 완료 슬롯의 접근 가능한 이름만 최종 상태로 갱신한다.
- CSS 애니메이션 종료 이벤트가 유실돼도 제한 시간 후 잠금을 해제하는 안전장치를 둔다.

## 솔버의 정확성 경계

일반화된 Spider Solitaire는 NP-Complete이므로 모든 4무늬 판의 불가능성을 짧은 시간 안에 증명한다고 약속하지 않는다. 솔버 결과는 다음 세 상태를 명확히 구분한다.

- `solved`: 실제 해답 수열을 찾았고, 같은 규칙 엔진으로 처음부터 끝까지 재생해 승리를 검증했다.
- `exhausted`: 중복 제거 후 탐색 공간을 모두 소진해 해답이 없음을 증명했다.
- `timeout`: 제한 시간 또는 노드 상한에 도달했다. 가능·불가능 어느 쪽으로도 판정하지 않는다.

게임은 `solved` 딜만 사용자에게 제공한다. `timeout`을 불가능 판으로 표시하거나 제공하지 않는다.

## 솔버 구조

### 순수 탐색 모듈

`apps/user-web/spider-solver.js`는 CommonJS와 Web Worker에서 함께 쓰는 무의존성 모듈이다.

- 입력: 난이도, 초기 덱 순서 또는 시드, 시간·노드 상한, 취소 신호
- 출력: 상태, 경과 시간, 방문 노드 수, 해답 이동 수열
- 탐색: 반복 심화 기반의 휴리스틱 DFS와 전이표를 사용한다.
- 상태 키: 카드 복사 ID가 아니라 열별 `무늬/랭크/공개 여부`, 재고 위치, 완료 수를 직렬화하며 대칭인 열을 정규화한다.
- 가지치기: 결과 상태 키가 같은 직전 이동의 단순 역행, 대칭인 빈 열 목적지, 상태 변화 없는 빈 열 이동처럼 상태 동등성이 증명되는 경우만 제거한다. 혼합 무늬 연결 같은 휴리스틱 열세 수는 제거하지 않고 탐색 순서만 낮춰 `exhausted`의 정확성을 보존한다.
- 우선순위: 숨은 카드 공개, 새 빈 열 생성, 같은 무늬 연결, 완성 묶음, 일반 연결, 재고 배분 순으로 휴리스틱 점수를 부여한다.
- 모든 `solved` 결과는 공개 게임 규칙 엔진으로 재생 검증해야만 외부에 반환한다.

### Worker 경계

`apps/user-web/spider-solver-worker.js`가 탐색을 수행해 메인 스레드의 창 드래그·크기 변경과 카드 렌더링을 막지 않는다. 요청마다 전용 Worker를 만들고 증가하는 ID를 붙인다. 동기 탐색 중인 Worker는 취소 메시지를 처리할 수 없으므로 새 게임·종료·제한 시간 때 `terminate()`하고 다음 요청에 새 Worker를 만든다. Worker 미지원이나 로드 실패 시 검증되지 않은 랜덤 딜로 후퇴하지 않고 사전 검증 풀을 사용한다.

## 검증 딜 제공 정책

### 실시간 경로

난이도별 벤치마크가 아래 조건을 모두 만족할 때만 새 무작위 시드를 Worker에서 실시간 검증한다.

- 100개 측정 딜의 평균 판정 시간이 1.0초 이하
- 최소 95개가 1초 안에 `solved` 또는 `exhausted`로 확정
- 해답 재생 검증 실패 0건

실시간 시도가 1초를 넘기면 즉시 취소하고 사전 검증 풀에서 딜을 가져온다. 사용자는 연속 재시도로 기다리지 않는다.

### 사전 검증 풀

실시간 기준을 충족하지 못한 난이도는 `solved`가 확인된 결정적 시드 목록을 사용한다.

- 빌드 전 생성 도구가 무작위 시드를 탐색하고 해답 재생까지 성공한 시드만 기록한다.
- 각 항목은 난이도, 시드, 해답 길이, 최종 상태 체크섬을 가진다.
- 난이도별 최소 256개 고유 시드를 배포 기준으로 삼는다.
- 런타임은 최근 사용한 시드를 세션 메모리에서 제외하고 나머지 중 무작위 선택한다.
- 풀 파일 누락·손상 시 새 랜덤 딜을 제공하지 않고 명확한 오류와 재시도 버튼을 표시한다.
- 해답 수열 자체는 클라이언트에 노출하지 않아 현재 힌트가 정답 전체를 보여주지 않게 한다.

## 벤치마크

`scripts/benchmark-spider-solver.js`가 단일 프로세스·단일 탐색 Worker 조건으로 난이도별 워밍업 10개 뒤 100개 시드를 측정한다.

기록 항목:

- OS, CPU 모델, Node 버전, 실행 시각
- 난이도별 평균, 중앙값, 95백분위, 최댓값
- 1초 내 확정 비율
- `solved`, `exhausted`, `timeout` 건수
- 평균·최대 방문 노드, 평균 해답 길이
- 해답 재생 검증 실패 건수

타임아웃도 실제 경과 시간으로 평균에 포함한다. 결과는 `docs/benchmarks/2026-08-25-spider-solver.md`에 원본 명령과 함께 저장한다. 측정 결과에 따라 각 난이도의 `live` 또는 `verified-pool` 선택을 같은 문서에 기록한다.

## 로딩과 배포

- 게임 지연 로더는 규칙 엔진과 게임 UI를 계속 먼저 로드한다.
- 솔버 Worker는 스파이더 새 게임이 필요할 때만 생성한다.
- 새 게임 중에는 기존 판을 유지하고 상태 패널에 `완료 가능한 판 확인 중…`을 표시한다. 실시간 검증 실패 시 지연 없이 검증 풀로 전환한다.
- `spider-solver.js`, `spider-solver-worker.js`, 검증 시드 파일을 Docker 정적 파일 목록과 Caddy `no-store` 경로에 등록한다.
- 외부 런타임 패키지와 서버 API는 추가하지 않는다.

## 테스트

### 자동 테스트

- 솔버가 작은 완성 가능/불가능 고정 상태를 각각 `solved`/`exhausted`로 판정한다.
- 반환된 모든 해답을 실제 엔진으로 재생해 승리한다.
- 취소·시간·노드 상한은 `timeout`과 구분되며 메인 스레드 상태를 변경하지 않는다.
- 딜 제공기는 `solved`가 아닌 시드를 절대 반환하지 않는다.
- 완료 원점 계산은 이동·배분·동시 다중 완성을 정확히 찾는다.
- 13장 연출 순서, 입력 잠금, 축소 모션, 취소 및 종료 정리를 검증한다.
- XP형 하단 완료 스택·중앙 상태 패널·오른쪽 5개 재고 묶음의 DOM 계약을 검증한다.
- 기존 이동, 힌트, 반복 실행 취소, 클래식 카드놀이 드래그 회귀 테스트를 유지한다.

### 브라우저 QA

- 1·2·4무늬에서 새 게임이 `solved` 딜만 시작하는지 상태 표시로 확인한다.
- 완성 묶음이 원본 열에서 왼쪽 아래 슬롯으로 이동하고, 연출 중 입력이 거절되는지 확인한다.
- 최소화·종료 도중 연출을 취소한 뒤 고스트나 잠금이 남지 않는지 확인한다.
- 작은 창·기본 창·최대화에서 XP형 하단 배치가 유지되는지 확인한다.
- Worker가 실패해도 검증되지 않은 랜덤 딜이 시작되지 않는지 확인한다.

## 완료 조건

- 난이도별 100딜 벤치마크 수치와 선택된 제공 경로가 보고된다.
- 사용자에게 시작된 모든 딜은 해답 재생이 완료된 `solved` 딜이다.
- 공개 자료로 관찰되는 XP 배치와 완료 이동을 현재 CC0 자산으로 재현한다.
- 전체 lint·테스트와 로컬 브라우저 QA가 통과한다.
- Microsoft 자산·코드·실행 파일을 저장소에 추가하지 않는다.
