# CLAW-167 CLI·오버레이 통합 업데이트 설계

## 목표

오버레이 앱에서 사용자가 업데이트를 확인하고 기본 업데이트 동작을 한 번 선택하면, 설치된 `clawad` CLI와 오버레이를 모두 최신 버전으로 갱신한다. 사용자가 별도로 터미널에서 `clawad update`를 실행할 필요가 없어야 한다.

## 범위

- Jira: CLAW-167, CLAW-168, CLAW-169
- 비공개 `clawad` 저장소는 CLI 자가 업데이트와 macOS 오버레이 교체 순서를 소유한다.
- 공개 `clawad-overlay` 저장소는 사용자의 업데이트 선택을 감지하고, 검증된 CLI 설치본에 업데이트를 위임한다.
- 광고 표시, 리워드 정책, 노출 원장, 텔레메트리 필드는 변경하지 않는다.
- PATH 검색, 셸 명령 문자열, 새 외부 패키지를 사용하지 않는다.

## 현재 구조

`clawad update`는 CLI 릴리스 manifest를 내려받아 새 버전을 별도 릴리스 디렉터리에 설치하고 활성 포인터를 바꾼다. 오버레이 업데이트는 별도 흐름이다. Windows에서는 `electron-updater`가 오버레이를 갱신하고, macOS에서는 오버레이가 기존의 검증된 `overlay-trigger.json` 포인터를 통해 CLI의 `overlay-update.js`를 실행한 뒤 종료한다.

이 구조에서는 오버레이만 갱신되고 CLI가 이전 버전으로 남을 수 있다. 또한 현재 CLI 업데이트는 동일 버전의 릴리스 디렉터리가 이미 있으면 오류로 종료하므로, 새 CLI 릴리스가 없는 오버레이 업데이트와 자연스럽게 결합할 수 없다.

## 설계

### 신뢰 경계

오버레이는 PATH에서 `clawad` 실행 파일을 찾지 않는다. 기존 `clawad-cli-bridge.js`가 `overlay-trigger.json`의 `node`와 `script`를 읽고, `script`의 basename이 정확히 `overlay-events.js`인지 확인한 뒤 같은 디렉터리의 `update.js`만 유도한다. 포인터가 없거나 손상됐거나 파일이 실제로 존재하지 않으면 CLI 업데이트를 시작하지 않는다.

오버레이는 CLI 내부 모듈을 import하지 않으며, 서버 정책·정산·부정방지 로직을 공개 저장소에 복제하지 않는다. 프로세스 경계만 사용한다.

### 공통 사용자 흐름

1. 오버레이가 새 오버레이 릴리스를 발견한다.
2. 사용자가 업데이트 프롬프트의 기본 동작을 선택한다.
3. 오버레이가 검증된 설치 포인터로 현재 CLI의 `client/update.js`를 백그라운드 실행한다.
4. 같은 오버레이 버전에 대한 CLI 업데이트 위임은 앱 프로세스 수명 동안 한 번만 시작한다.
5. CLI 위임이 불가능하거나 실패해도 오버레이 자체 업데이트를 계속한다.

CLI 프로세스는 셸 없이 `node update.js` 형태로 실행한다. 실행 결과는 오버레이 로그에 종료 코드로 남기되 UI 스레드를 기다리게 하지 않는다.

### Windows

Windows에서는 사용자가 `지금 업데이트`를 선택한 직후 다음 두 동작을 병행한다.

1. 검증된 CLI의 `update.js`를 비동기로 시작한다.
2. 기존 `electron-updater.downloadUpdate()`를 시작한다.

CLI 업데이트는 새 CLI를 독립 릴리스 디렉터리에 설치하고 활성 포인터만 전환하므로 실행 중인 오버레이와 충돌하지 않는다. 오버레이 다운로드가 끝나면 기존처럼 재시작 동의를 받고 `quitAndInstall()`을 호출한다. 한쪽 실패는 다른 쪽의 성공을 되돌리지 않는다.

### macOS

macOS에서는 사용자가 업데이트를 선택하면 검증된 CLI의 `update.js`를 시작한 뒤 오버레이가 종료한다. CLI 업데이트 프로세스는 다음 순서를 책임진다.

1. CLI manifest를 검증한다.
2. 새 CLI 버전이면 별도 릴리스 디렉터리에 설치하고 활성 포인터를 전환한다.
3. 이미 같은 CLI 버전이 활성 상태면 `up-to-date` 성공으로 처리한다.
4. 새 CLI가 활성화됐다면 새 설치본의 `overlay-update.js`를 선택하고, 그렇지 않으면 현재 활성 설치본의 스크립트를 선택한다.
5. 선택한 스크립트가 오버레이 종료를 기다린 뒤 overlay manifest·SHA-256을 검증하고 앱을 교체한다.
6. 교체 성공 또는 안전한 실패 복구 후 오버레이를 다시 실행한다.

CLI 갱신이 실패하면 현재 활성 CLI의 `overlay-update.js`로 오버레이 갱신을 계속 시도한다. 따라서 CLI 오류가 오버레이 업데이트를 막지 않는다. 오버레이 교체 실패 시 기존 `overlay-update.js`의 복구·재실행 동작을 유지한다.

### CLI 동일 버전 처리

manifest 버전이 현재 활성 버전과 같고 활성 설치본의 필수 파일이 존재하면 다운로드·재설치를 하지 않고 성공 결과 `up-to-date`를 반환한다. 동일 버전 디렉터리가 있지만 활성 포인터가 유효하지 않은 경우에는 성공으로 간주하지 않고 기존 복구 오류를 유지한다.

CLI 업데이트 기능은 테스트할 수 있도록 다운로드·설치·활성화 단계를 함수 경계로 분리하되, 기존 CommonJS 구조와 외부 의존성 없음 원칙을 유지한다. 직접 실행 시의 종료 코드는 다음과 같다.

- CLI와 필요한 오버레이 갱신이 모두 성공하거나 이미 최신: 0
- CLI만 실패했지만 오버레이 갱신 성공: 0, CLI 실패는 stderr에 기록
- 오버레이 갱신이 필요한 macOS에서 오버레이 갱신 실패: 1
- Windows/Linux의 CLI 갱신 실패: 1

## 오류 처리

- CLI 미설치 또는 손상 포인터: 오버레이 로그에 `unavailable`을 남기고 오버레이 업데이트 계속
- CLI 프로세스 시작 실패: 오버레이 로그에 오류를 남기고 오버레이 업데이트 계속
- 중복 업데이트 이벤트: 같은 대상 오버레이 버전에 대한 CLI 프로세스를 다시 시작하지 않음
- CLI manifest·체크섬·패키지 검증 실패: 활성 CLI 포인터를 바꾸지 않고 기존 버전 유지
- 새 CLI health check 실패: 기존 CLI 설치를 다시 활성화
- macOS CLI 갱신 실패: 기존 활성 CLI로 오버레이 갱신 시도
- macOS 오버레이 종료 시간 초과 또는 교체 실패: 기존 오버레이 보존·재실행
- Windows 오버레이 다운로드 실패: CLI 업데이트 결과는 유지하고 기존 오류 UI 표시

## 사용자 표시

기존 업데이트 프롬프트의 버튼 수와 전체 흐름은 유지한다. 안내 문구는 업데이트 동작이 오버레이와 CLI를 함께 갱신한다는 의미로 5개 지원 언어에서 수정한다. CLI 미설치나 CLI만의 실패 때문에 추가 차단 대화상자를 만들지 않는다.

## 광고·안내 표기 시각적 위계 (CLAW-168)

현재 `[광고]`·`[안내]` 표기와 `안내 끄기` 버튼이 같은 회색 배경, 패딩, 모서리, 굵기를 사용해 모두 같은 종류의 배지처럼 보인다. 세션 HUD의 상태 칩을 작업 예시로 삼아 역할을 분리한다.

- `[안내]`는 초록색 반투명 배경과 초록색 전경색을 가진 상태 칩으로 표시한다.
- `[광고]`는 주황색 반투명 배경과 주황색 전경색을 가진 상태 칩으로 표시한다.
- 표시광고법 불변식을 위해 `[광고]`의 대괄호를 포함한 정확한 문자열은 유지한다.
- 두 칩은 세션 HUD의 `.state-chip`과 같은 10px 글자, 500 굵기, 1 line-height, 2px 5px 패딩, 3px 모서리를 사용한다.
- 밝은 모드에서 안내는 `rgba(22, 163, 74, 0.13)`/`#16a34a`, 광고는 `rgba(245, 158, 11, 0.15)`/`#b45309`를 사용한다.
- 어두운 모드에서 안내는 `rgba(22, 163, 74, 0.20)`/`#4ade80`, 광고는 `rgba(245, 158, 11, 0.20)`/`#fbbf24`를 사용한다.
- `안내 끄기`는 의미와 키보드 접근성을 위해 `<button>`을 유지하되 배경, 테두리, 모서리, 배지 패딩을 제거한다.
- `안내 끄기`는 보조 텍스트 색상과 밑줄을 사용하고 hover·focus-visible에서 전경색과 밑줄이 선명해진다.
- 버튼 클릭은 계속 `stopPropagation()`을 호출해 안내판 전체 클릭 동작과 분리한다.

## 두 행 광고 레이아웃 (CLAW-169)

현재 `#text`가 `row1` 안에서 최대 두 줄을 차지하고 광고주·적립이 별도 `row2`에 남는다. `AD_STRIP_HEIGHT`도 안내 높이에 본문 한 줄 높이를 추가하므로 두 줄 본문이 총 세 줄 높이를 만든다.

패널 내부를 CSS Grid의 3열 2행으로 바꾼다.

| Grid 위치 | 내용 |
| --- | --- |
| 1열 1행 | `[광고]` 또는 `[안내]` 칩 |
| 2열 1~2행 | 최대 두 줄 본문 |
| 3열 2행 | 광고주, 예상 적립, 외부 링크 표시 |
| 2열 2행(안내만) | 밑줄 형태의 `안내 끄기` |

본문 열은 `minmax(0, 1fr)`로 줄어들 수 있고 metadata 열은 내용 폭을 사용한다. metadata 내부에서는 기존처럼 광고주가 먼저 줄어들고 말줄임되며 예상 적립은 `flex: 0 0 auto`와 `white-space: nowrap`으로 보존한다. 본문은 두 행 높이 안에서 `-webkit-line-clamp: 2`를 유지한다. 안내 본문은 한 줄로 제한하므로 둘째 행의 `안내 끄기`와 겹치지 않는다.

광고와 안내 모두 같은 두 행 창 높이를 사용한다. `AD_STRIP_HEIGHT`에 한 줄을 추가하던 CLAW-162 보정은 제거하고 `stripHeight()`는 유효한 모든 표시 종류에 동일한 `NOTICE_STRIP_HEIGHT`를 반환한다. 구 payload나 알 수 없는 kind도 같은 안전한 높이를 사용한다.

대안인 JavaScript 문자열 분할은 채택하지 않는다. 폰트, OS, 화면 배율에 따라 측정 결과가 달라지고 renderer가 본문을 별도 문자열로 재작성해야 하기 때문이다. Grid 방식은 DOM 텍스트를 그대로 유지하면서 줄 수와 metadata 기준선만 제약한다.

## 테스트

### clawad

- 활성 CLI가 manifest와 같은 버전이면 다운로드 없이 `up-to-date`가 된다.
- 새 CLI 설치 성공 후 새 설치본의 macOS 오버레이 업데이트 스크립트를 선택한다.
- CLI 설치 실패 시 기존 활성 설치본으로 macOS 오버레이 업데이트를 시도한다.
- macOS 오버레이 업데이트 실패가 최종 실패 종료 코드로 전달된다.
- Windows/Linux에서는 오버레이 교체 스크립트를 실행하지 않는다.
- 기존 체크섬 검증, rollback, BOM 제거 테스트가 유지된다.
- `npm.cmd run lint`와 `npm.cmd test`를 실행한다.

### clawad-overlay

- 검증된 포인터에서 `update.js`만 유도한다.
- 임의 basename, 없는 Node, 없는 스크립트, 손상 JSON을 거부한다.
- Windows 업데이트 선택 시 CLI 위임과 `downloadUpdate()`가 각각 한 번 시작된다.
- 같은 대상 버전의 중복 이벤트는 CLI를 한 번만 시작한다.
- CLI 위임이 불가능하거나 시작에 실패해도 Windows 다운로드를 계속한다.
- macOS 업데이트 선택 시 CLI를 시작하고 앱을 종료한다.
- macOS에서 CLI가 없으면 기존 릴리스 페이지 fallback을 유지한다.
- 관련 단위 테스트와 변경 파일 구문 검사를 실행하고, 전체 테스트의 기존 baseline 실패 수가 증가하지 않는지 확인한다.
- 광고·안내 칩의 밝은/어두운 색상 토큰과 `안내 끄기` 링크형 버튼 스타일을 정적 계약 테스트로 검증한다.
- 광고 패널이 3열 2행 Grid를 사용하고 본문과 metadata가 둘째 행을 공유하는지 검증한다.
- 광고와 안내의 높이가 동일하며 CLAW-162의 추가 한 줄 높이가 제거됐는지 `clawad-ad-width` 단위 테스트로 검증한다.
- 한 줄·두 줄 광고, 긴 광고주, 적립 없음, dismissible 안내의 renderer 동작을 기존 DOM 하네스로 검증한다.

## 문서와 릴리스

- `docs/design/overlay-contract.md`에 오버레이가 `update.js`를 유도할 수 있는 계약과 검증 조건을 기록한다.
- 오버레이 공개 문서에는 CLI 실행 경계만 기록하고 비공개 정책 구현은 기록하지 않는다.
- 구현은 두 저장소의 `feat/claw-167-unified-update` 브랜치에서 CLAW-167·CLAW-168·CLAW-169를 함께 처리하고 각각 `develop` PR로 통합한다.
- 통합 후 CLI 0.1.18, 오버레이 0.1.9 패치 릴리스를 준비하고 `develop`에서 `main`으로 PR을 만든다.
- GitHub CLI 릴리스 manifest와 오버레이 manifest를 원격 검증한다.
- npm 인증이 유효하면 `@clawad/cli@0.1.18`도 게시하고 레지스트리 버전을 검증한다. 인증이 없으면 GitHub 기반 `clawad update` 릴리스는 완료하되 npm 게시만 명시적 blocker로 보고한다.
